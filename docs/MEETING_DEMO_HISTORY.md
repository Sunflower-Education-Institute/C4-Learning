# Meeting Demo：基础静态网页计划

## 1. 本阶段目标

在不依赖 Node.js、数据库、真实注册/登录或第三方服务的前提下，先做一个可以用于会议演示的 Sunflower Education 静态网站。

首版应同时满足：

- 可以直接部署到 GitHub Pages；
- 页面稳定，不会因为数据库或服务器未连接而报错；
- 能清楚说明网站的目标、内容和未来功能；
- 使用少量真实资源资料，而不是完全虚构的占位内容；
- 后续可以逐步替换为真实 API、用户系统和数据库；
- 最终可另存一份离线演示版本，降低会议现场网络风险。

本轮只制定计划，不创建 HTML、CSS 或 JavaScript 文件。

## 2. 建议的基础静态版本范围

### A. 首页

- Sunflower Education 名称、品牌定位和一句核心介绍；
- “Browse Resources / Explore Resources”主要按钮；
- 三到四项核心价值：可信资源、家长与教育者评论、容易筛选、研究者总结；
- 3–6 个精选资源卡片；
- About、Contact、Sign In 等导航入口；
- 页脚和必要的免责声明。

### B. 资源库

- 展示约 10–20 条经过整理的真实资源；
- 每张卡片显示名称、年龄、学科、类型、价格、评分和资源链接；
- 在浏览器内实现关键词搜索、学科/年龄/价格筛选和排序；
- 数据从本地 JSON 或 JavaScript 文件读取，不访问数据库。

### C. 资源详情展示

- 资源名称、简介、适合年龄、学科、价格和官网链接；
- SEE 示例评分；
- 优点、注意事项和示例评论；
- 收藏、写评论等按钮可以打开演示提示或使用浏览器本地存储，不提交到服务器。

### D. About / 网站说明

- SEE 的使命、目标用户和资源筛选方式；
- 负责人/研究者简介；
- 说明会议版为产品演示，未来将接入社区评论和个性化推荐。

### E. 登录与注册的“界面预览”

- 可以显示 Sign In、Create Account、Profile Survey 等界面；
- 必须明确标记为 Demo；
- 不创建真实账号、不保存密码、不暗示已经连接安全认证系统。

## 3. 首次会议演示建议流程

1. 首页介绍 SEE 解决的问题和目标用户。
2. 点击进入资源库。
3. 演示关键词、年龄、学科或价格筛选。
4. 按评分或评论数排序。
5. 打开一个资源详情并查看评分、摘要和示例评论。
6. 点击收藏或写评论，说明当前为前端演示，正式版会连接用户账户。
7. 展示登录/注册及家庭资料问卷的未来界面。
8. 最后说明数据库、真实评论、推荐和后台管理的下一阶段计划。

| 星级评分和评论界面 | 可以 | 详情页、评论组件、旧数据库模型 | 静态版使用精选示例或明确标记的演示数据 |

| 中文内容/双语翻译 | 部分可以 | 旧翻译入口和相关代码 | 首版优先英文；确认文案后再补双语 |

## 5. 目前已确认可复用的项目材料

- 恢复版中已有首页、资源库、资源详情、About、Contact、用户资料、问卷和多个管理员页面；
- 本地 JSON 中有数十条资源记录，字段包括名称、儿童年龄、类型、价格、推荐来源、访问链接和学科分类；
- Excel 文件可作为后续人工维护资源表的来源；
- 数据库 schema、接口和旧组件可以帮助我们保持未来动态版的数据结构一致；
- 已有一张负责人照片和项目级图片，但资源封面图片仍需要另行整理；
- 用户 CSV 属于敏感资料，不应进入公开 GitHub 仓库或会议静态网站。

## 6. 首版开始前仍需由你确认或补充的内容

- 网站最终显示名称：`Sunflower Education`、`SEE`，或二者组合；
- 首页最希望观众记住的一句话；
- 会议主要观众是谁，以及希望他们会后采取什么行动；
- 首批重点展示的 6–12 个资源；
- 是否展示负责人姓名、照片和简介；
- 评分是使用真实历史评分、人工示例评分，还是暂时不显示数字；
- 示例评论是否有获得公开展示许可；
- 首版语言是英文、中文，还是中英双语；
- GitHub 仓库计划公开还是私有。

## 8. 建议的实施顺序

### 第一阶段：最小静态版

- 首页；
- 资源库；
- 10–20 条本地资源数据；
- 搜索、筛选、排序；
- 1 个通用资源详情展示；
- About；
- 响应式手机布局。

### 第二阶段：会议演示增强

- 登录、注册、Profile Survey 的演示界面；
- 收藏和评论的本地模拟；
- 更完整的评分和评论样例；
- 中英文切换；
- 会议专用讲解顺序和离线备份。

### 第三阶段：会议后动态化

- 选择正式数据库和认证服务；
- 将静态资源数据迁入数据库；
- 接入真实注册、登录、收藏、评论和管理后台；
- 接入照片存储；
- 再考虑 AI 摘要、翻译和个性化推荐。

## 9. GitHub 发布注意事项

- GitHub Pages 适合当前纯静态 Demo；
- 不要把用户 CSV、密码、API Key、数据库连接串或私密评论上传到公开仓库；
- 外部资源链接可以保留，但会议前应逐一检查是否可访问；
- 图片必须确认授权，避免直接复制第三方网站图片；
- 如果以后接入登录、数据库或服务器端功能，GitHub 继续用于保存源码，但网站后台需要部署在支持服务端功能的平台上。

## 10. 当前结论

基础静态版可行，而且原项目中已经能找到大部分页面结构、产品文案框架和资源字段。真正需要补充的主要是：精选资源内容的清理、资源封面图片、最终品牌文案、可公开使用的评分/评论，以及会议展示重点。

建议先完成“首页 + 资源库 + 资源详情 + About”的最小版本，再增加模拟登录和评论功能。这样能最快得到稳定、可在 GitHub Pages 发布、也可离线打开的会议 Demo，同时不会被旧 Node.js 或数据库问题拖慢。

## 11. 已确认的设计与内容决定（2026-09-03）

- 网站页眉直接引用 `SEE Images and Logo/Transparent Logo.png` 中的正式 Logo，不重新绘制或改造脑形树冠；
- 首页保留大幅向日葵主视觉；辅助图案只使用原 Logo 中完全一致的脑形树冠、内部线条和树干结构，删除黄色圆形、机构文字与标语，并将黑色线条改为很淡的暖棕色；
- 整体配色保持积极、温暖，但比第一张概念图降低约 15–20% 饱和度；
- 网站默认语言为英文；右上角使用地球仪图标打开语言菜单，首批提供 English 和中文，并预留更多语言；
- 最新资源表共有 39 个资源，资源库第一版计划全部收录；
- 资源库显示全部 39 个资源，通过分页或 Load more 浏览；`39 resources` 表示当前筛选结果数量，筛选后动态更新；
- 去掉容易与筛选结果混淆的 `Featured Resources` 标题，搜索结果区使用 `Explore learning resources`；如果未来增加首页精选区，应单独放置并明确说明推荐依据；
- 公开资源卡片不显示 Source ID；Source ID 仅用于内部关联资源、评论、标签和图片；
- 卡片标题下显示 1–2 行简短介绍，帮助家长快速判断资源是否适合；
- Initial SEE Score 来自 SEE Leader 对每个网站的详细评测，首版页面显示评分但暂不解释计算来源；
- 其他参与者评分和评论作为独立内容保留，未来可形成综合评分；
- 未来资源图片统一使用 Source ID 命名，例如 `see1_abcmouse.jpg`；
- 图片尚未加入时，网页使用统一占位区域，不显示伪造封面。
